# AutoClick 修改任务时间与星期设计

日期：2026-10-07（Asia/Shanghai）

状态：2026-10-07 用户已分别确认设计与实现计划；功能已实施，本地检查及模拟器验收通过。本文及实现计划不自动提交。

## 目标与边界

用户能直接在主页修改已保存任务的执行时间和每周执行星期，无需重新录制。使用现有“定时任务”卡片和应用内弹框，不依赖悬浮录制界面。

保留原点击位置、相对间隔、录制保护、保存时区、任务启用状态、最近结果和已消费记录。保留现有 WorkManager、15 分钟迟到窗口及无障碍前置要求；另有精确调度设计和计划，本轮不实施或覆盖它们。不修改主 app、共享手势库、图标和依赖。

## 交互

- 有已保存任务时，在任务操作区增加“修改时间”。执行准备、倒计时、试运行和执行中禁用，保存中禁止重复点击。
- 弹框标题“修改任务时间”；24 小时制时间输入及星期多选，预填保存值，星期按周一至周日排列。
- 星期不能为空；提示“请至少选择一个执行星期”，保留输入。
- 按钮为“保存修改”“取消”。取消、返回或点击弹框外部在未保存时丢弃本次编辑，不影响原任务；保存进行中不允许重复操作。
- 支持小屏、横屏、大字体滚动；旋转保留未保存的时间和星期。弹框显示任务的保存时区，本轮不切换时区；设备时区已变时明确说明仍使用原时区，沿用既有时区不匹配保护。
- 无任务不显示入口。缺少录制保护的旧任务继续提示重新录制，禁止通过修改时间绕过要求。
- 无障碍就绪状态丢失、任务被替换或执行开始时，关闭尚未提交的编辑并提示需要重新打开；保存端还须再次检查，不能只依赖按钮置灰。
- 时间和星期没有改变时直接关闭，不更换调度身份、不取消工作、不清除异常状态，也不暗中重新启用。

## 保存与调度

1. 编辑草稿只包含原任务身份、时、分和星期，不包含重新从浮窗读取的录制内容。
2. 保存使用独立的更新操作。在现有串行修改边界内重读任务、核对原身份，取得与定时/试运行互斥的短暂编辑保留权，再次检查停止及执行状态。
3. 保留稳定的 `scheduleId`，更新可失效旧工作及旧回调的 `id`。复制原任务的录制、时区和启用状态，仅更新时间和星期。
4. 已启用任务替换唯一周期工作；旧工作不得再获取点击执行权、记录结果或覆盖新计划。已停用任务保存新配置且保持无有效工作，不调用允许自动执行的方法。
5. 保存成功后刷新主页和匹配工作；下次时间从实际调度状态呈现，不能仅凭配置宣称安排成功。旧工作取消有竞争时，还要由新身份阻止它继续点击。
6. 最近执行结果与本次控制/调度错误独立。安排失败时尽力持久化停用并取消工作，显示“调度失败，请重新启用”；若停用落盘或取消也失败，明确报告状态未确认，不显示保存成功，不编造已停用。失败期间保持自动执行阻断，用户可通过明确启用恢复。

紧急停止优先于编辑，能够撤销编辑保留权；修改操作不能在紧急停止后重新打开执行门。已发送的手势无法撤销；编辑与开始点击的互斥用于避免在编辑保存中产生新的手势。

## 日期与防重复规则

- 下一次必须严格晚于保存时刻，且星期被选中。新时间今天已过或恰好到达，安排下一次符合条件的日期，不补执行。
- 今天未开始过，且新时间仍在未来、今天被选中时，可安排今天。
- 同一保存任务在其保存时区内一天最多自动开始一次。今天上午开始过，改到今天下午也不能再自动开始；失败、取消和中断不解除消费保护。
- 保留消费水位，按保存时区的日期比较：已消费日期及更早日期都被阻断，防止改时间或时钟回拨重放。新的未来日期可执行。
- 保存、停用再启用、启动恢复、工作对齐和下一次时间展示都使用一致的消费规则。旧任务身份不能领取新任务发生次数。手动试运行仍独立，不消耗定时日期。

## 验收

- 逻辑：时间边界、星期、跨周、同日改早/改晚、已消费日期、回拨、夏令时及保存时区。

- 竞争：编辑与定时/试运行争抢执行权，编辑期间紧急停止，编辑打开后任务替换或删除。
- 界面：预填、保存、取消、星期为空、旋转、权限丢失、执行中禁用，以及正常/大字体/横屏截图。
