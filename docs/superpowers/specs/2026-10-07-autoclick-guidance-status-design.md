# autoClick 无障碍前置引导与任务状态设计

日期：2026-10-07（Asia/Shanghai）

状态：用户已分别确认设计及实现计划；2026-10-07 已实施并完成本地与模拟器验收。当前工作区改动保留，未自动提交。

## 目标与范围

本轮围绕已讨论的两个目标：无障碍作为应用功能的前置条件，用户能主动获得开启/恢复引导；任务卡片展示下一次计划、当前状态及最近结果。

使用现有主页卡片，详细说明按需展开；仅用文字评审。任务编辑继续暂缓。

本轮保留现有 WorkManager 调度、发生次数消费、点击保护、10 秒后台重连等待和 15 分钟迟到截止规则。到点未开始、准点触发方案及迟到容忍阈值的业务合理性列为后续问题，不在本轮修改。展示当前截止时间不代表用户已认可 15 分钟为长期业务要求，也不承诺期限内必定启动。

## 一、无障碍前置检查

应用首次进入、每次回到前台及从系统设置返回时立即检查系统授权与实际服务连接。可交互前台期间持续检查；检查未完成时显示检查状态，不能把默认未开启状态当作实际结果弹框。后台不主动展示界面。

| 状态 | 展示与操作 |
| --- | --- |
| 未开启 | 阻止使用主页功能；弹框说明“请先开启 AutoClick 无障碍服务”，提供“去开启”“退出应用” |
| 已开启、未连接 | 显示“正在连接服务”，最多等待 10 秒；允许退出 |
| 连接等待超时 | 阻止使用主页功能；弹框提供“去设置”“退出应用”，说明在系统设置中关闭后重新开启 AutoClick 服务 |
| 已连接 | 自动收起相关引导，开放主页功能 |

系统授权与实际连接都满足才视为就绪。打开设置只是导航，不代替用户授权；连接恢复不会自动开始录制、试运行或重放点击。

点击“退出应用”或引导期间按返回键都结束当前 AutoClick 界面、回到此前页面；点击弹框外部不能绕过检查。退出保留录制及任务，不等同于紧急停用、删除或系统强行停止应用。

同一次持续异常不叠加或重复弹框。等待基准在同一次断连期间保持连续，前台刷新或重复重组不会重新开始 10 秒等待。前台连接丢失时恢复前置引导；退出到设置时停止可交互前台计时，返回后重新检查，并为系统重新绑定提供连接等待窗口。

引导要服从页面生命周期：界面退到后台或销毁后不弹框、不保留旧界面引用；旋转重建不能产生多个弹框或规避前置检查。已有后台任务及紧急停止控制保留原有生命周期和保护规则。

## 二、任务卡片

位置：在“定时任务”卡片的时间、星期、点击数量下方增加“当前状态”；下方独立保留“最近结果”和现有操作按钮。试运行结果继续单独显示。

示意文字（示例日期与结果不代表真实记录）：

```text
09:00                         已启用
周一至周五 · 3 个点击

当前状态
下次：明天（周四）09:00

最近结果
上次 · 全部点击手势已完成

[停用任务]   [删除任务]
[5 秒后试运行]
```

| 情况 | 当前状态 |
| --- | --- |
| 尚无任务 | 保留创建任务引导，不展示下一次时间 |
| 已停用 | “任务已停用”，不暗示正在等待执行 |
| 正常等待未来计划 | “下次：今天/明天/具体日期（星期）HH:mm” |
| 当前定时 Worker 正在准备，尚未进入手势执行 | “执行准备中” |
| 当前定时执行会话活跃 | 展示已有执行进度；不把手动试运行当作定时执行 |
| 本次计划已到、确认仍未开始 | “尚未开始 · 已延后 N 分钟”；第二行按现有规则显示“HH:mm 后将跳过本次” |
| 本次已结束、已开始过不允许重放，或已超时 | 展示下一次有效计划；最近结果保留本次状态；仅已消费不能推断为执行成功 |
| 时区改变 | “时区已改变，需重新设置任务”，提供现有重新保存流程的说明 |
| 实际调度信息未就绪或不能确认 | 显示读取/异常状态，不编造下一次时间或延迟原因 |

“下次”指计划时间，不是保证开始的时间。保留简短说明“系统可能延后”。到点未开始只是对现状的描述，本轮不增加补执行、重试或改变截止阈值。

## 三、状态来源与刷新

状态展示综合已保存任务、该任务对应的 WorkManager 工作、当天发生次数消费记录及当前执行会话。匹配任务标识与工作标签，不能读取被替换任务、一次性测试工作或手动试运行作为正常定时任务。

不能只使用“当前时间之前/之后”计算下一次时间：保存时已过当天时间的任务实际计划在未来；已经错过触发但仍待启动的旧任务则需要显示当次状态。当前执行和消费记录优先于纯时间推算，避免正在执行却显示超时，或已经开始过却暗示稍后会自动重放。

前台观察任务、工作及会话变更，并在可交互前台按秒更新时间。返回前台立即刷新；时间、日期或时区改变后重新计算。退到后台停止用于展示的计时和订阅，不改变后台调度。

纯状态计算与页面渲染分开；无障碍引导由前台页面生命周期管理；已有后台 Worker 继续负责实际点击与最终执行结果。共享 accessibilityCore 的行为不因本轮 AutoClick 引导而改变。

## 四、最近结果与恢复操作

当前连接状态和历史结果分开。例如服务恢复后，当前显示已连接，仍保留上次“连接超时未执行”。服务恢复不意味着本次补执行。

新结果携带明确的原因标识，关联原任务/发生次数，作为展示数据；保留可读原文。旧记录没有原因标识时原样展示，不靠模糊字符串推断失败原因。保存展示信息仍遵守既有任务身份及停止保护，旧任务结束后不能覆盖新任务或紧急停止状态。

| 已确认的结果原因 | 用户操作 |
| --- | --- |
| 无障碍权限/连接异常 | 前置弹框处理；连接后的任务卡片保留历史原因 |
| 屏幕未亮/锁屏、目标应用不符 | 展开“执行前准备”说明：亮屏解锁、打开正确目标页面 |
| 缺少环境信息、屏幕方向/尺寸不符 | 展开重新录制说明，引导现有录制流程，不自动清空 |
| 调度恢复失败、任务已停用 | 展示原因，使用现有启用操作，不自动启用 |
| 超时或部分点击后停止 | 保留结果并说明本次不会自动重放；需要试运行时沿用现有真实点击确认 |
| 原因未知 | 保留原结果及时间，不归因于省电限制或其他未证实原因 |

不自动打开目标页面、不自动解锁、不新增录制或任务编辑能力。主页是 AutoClick 自己的前台，不把“目标应用当前不在前台”作为打开主页的错误；实际点击前继续做原有保护检查。

## 五、验收标准

- 未开启时自动引导；“去开启”导航正确；拒绝或返回退出界面，不能进入主页使用功能。
- 授权但短暂断连时等待；连接成功收起引导；持续断连超过 10 秒提示恢复；前台刷新不重置等待，不叠加弹框。
- 从设置返回、前后台切换及界面重建后状态正确；后台不弹框。
- 退出及查看说明不清空录制、不删除或停用原任务，不触发真实点击。
- 下一次时间覆盖今天、明天、指定星期、周末跨周和跨日；保存时间已过的任务不会误报当天等待。
- 停用、替换、手动试运行、定时准备/执行、消费但未完成、超时及未知调度状态显示准确；历史结果不被连接状态覆盖。
- 时区/时间变化后显示正确，仍沿用已有 Worker 的执行保护及不自动重放规则。
- 在已启动模拟器上做短时验证，采用下一分钟定时或短连接等待；不以新增长等待作为验收前提。原数据/权限设置快照恢复；真机验收继续按用户要求暂缓。

以上为设计验收目标，尚未声称实现或验证通过。实现步骤及具体测试命令留待设计评审通过后的实现计划。

## 后续问题：定时触发可靠性

- 当前 WorkManager 不能保证按计划时间启动，15 分钟迟到截止可能导致当次不执行。
- 比较适合业务的触发方案（包括精确闹钟），确定必要权限、恢复行为与设备条件。
- 与用户确认允许迟到多久，以及迟到后是否仍有业务价值；重新评审现有 15 分钟默认值。
- 此问题独立走设计评审、实现计划确认、实施与验证流程。

先评审本设计文档，修改并确认后给出实现计划。实现计划获得用户明确确认后才能修改功能代码。当前工作区已有大量未提交变更，本轮不自动提交、发布或改动无关主 app。
