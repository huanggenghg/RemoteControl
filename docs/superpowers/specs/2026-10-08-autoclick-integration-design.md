## 3. 用户操作与状态

保留现有主页“修改时间”、24 小时时分输入、星期多选、预填、取消、旋转保留草稿及单次保存行为。编辑只改变时、分和星期，不改变点击序列、间隔、保护、保存时区、稳定计划身份、最近执行结果和录制草稿。

| 编辑时情况 | 保存后的行为 |
| --- | --- |
| 任务已启用，定时权限有效，时区未变 | 使旧调度身份失效，取消旧安排，通过精确闹钟登记新的未来安排；只有实际确认登记成功，才显示新的下次计划 |
| 任务已停用 | 保存新时间/星期并保持停用，不登记闹钟，不暗中启用；编辑本身不要求授予定时权限 |
| 原任务仍标记启用，但保存时发现定时权限已丢失 | 保留新配置，落盘停用及缺权状态，明确提示“时间已修改，定时权限未开启，任务未启用”；重新授权后仍需用户明确启用 |
| 保存时区与当前时区不一致 | 沿用保存时区，保存新配置但不得启用或重新安排；保持/进入时区异常状态，说明需按现有入口重新保存以更新时区 |
| 时间和星期未改变 | 直接关闭编辑，不更换身份、不取消/重排、不清除异常状态；权限与时区的独立前台检查仍按原规则工作 |
| 处于定时准备、倒计时、试运行或执行中 | 禁止编辑；弹框尚未提交时遇到任务替换、执行开始或无障碍掉线，关闭并说明原因 |
| 保存中 | 禁止重复保存和取消；旋转不重复提交，紧急停止仍然可用 |
| 缺少新版录制保护信息 | 沿用现有安全限制和说明，后续旧任务恢复事项再提供新交互 |

成功提示必须反映最终状态，不能只根据打开弹框时的 `enabled` 快照宣称任务仍启用。缺权导致保留配置并停用，属于明确的保存结果，不应伪称全部成功或配置保存失败。

## 4. 调度、身份与防重复

精确闹钟是唯一的自动点击入口，旧 WorkManager 入口继续零点击。编辑不重新引入周期工作。首手势必须满足 `T <= firstDispatchAt < T + 5000ms`，窗口覆盖连接、停止控件、环境检查和第一点原始等待。开始后的后续点保留原间隔。

保留稳定的 `scheduleId`；有实际配置变更时更新任务 `id`，使旧闹钟、旧执行回调和旧编辑快照失效。旧事件即使在取消后送达，也不能获取新任务的执行权或覆盖新结果。

区分两个已有记录的含义：

- `consumed_at`：执行领取成功即消费。对同一录制计划，在保存时区内已消费的日期及更早日期均不可再次自动开始。领取后取消、失败、进程结束或首手势尚未发出，都不释放该日期。
- `closed_at`：已跳过/终结事件的水位，防止旧事件被再次接纳；仅跳过而未领取执行的情况，不自动消费整天。

因此：

- 今天上午已领取执行，再改到今天下午，只安排之后符合星期的未来日期。
- 今天尚未领取执行，用户明确改到今天未来时间且今天被选中，可以安排今天；即使之前某个旧事件已经超时跳过，也不等于补投那个旧事件。
- 新时间已经过去或恰好到达，不补执行，安排严格未来时间。
- 停用/启用、编辑、冷启动、系统恢复、接纳与执行领取，都使用一致的消费日期判断，不能仅依赖主页显示或下一次计算。
- 手动试运行继续独立，不消耗自动执行日期。

新保存的录制仍按现有规则创建新计划；普通时间编辑不得通过更换 `scheduleId` 清空消费保护。

## 5. 互斥、保存和失败处理

任务修改继续在控制器的串行边界内协调，编辑保留权和试运行/定时执行共用现有执行门。除当前运行会话外，精确调度的 `active/PREPARING` 也视为正在准备，不允许编辑抢先覆盖已接纳事件。

保存前重读任务身份、无障碍连接、执行状态、停止状态、权限及保存时区。持有编辑保留权时，新的定时/试运行不能开始。紧急停止能立即撤销保留权，保存后续步骤不能再次打开自动执行门；停止发生在取保留权之前，也不能被随后编辑撤销。

配置与对应调度状态在存储锁内一致落盘。平台闹钟登记采用现有 ARMING → ARMED 确认流程。控制错误、未来调度状态和真实历史结果分别保存，安排失败不能覆盖最近真实点击结果。

若落盘、取消、安排或最终确认失败：

- 自动执行门保持阻断，尽力取消相关安排并持久化停用/安排失败状态。
- 新身份阻止迟到旧事件执行，不将“调用了取消”视为唯一保障。
- 能确认保留配置且停用时，明确告知需重新启用；无法确认落盘或取消时，显示“调度状态未确认”，不能伪称已停用或保存成功。
- 协程取消也执行必要清理，不自动重试真实手势。

## 7. 验收标准

本地检查：

- 精确定时五秒边界、日期消费与跳过水位、时区及回拨、同日改晚、严格未来时间、身份失效。
- 编辑与准备/执行/试运行互斥、停止先于或发生于保存、缺权/时区状态、安排与存储失败。
- 已停用编辑不启用、无修改不重排、草稿/录制/保护/历史保留。
- Debug 应用和测试包构建、受影响单元测试、Lint、差异与来源清单检查。

模拟器联合验收使用已有模拟器，先备份真实应用数据、授权和显示设置，结束后恢复核对：

1. 经主页修改未来时间，走生产精确闹钟入口，记录计划时间、首手势、测试按钮真实收到时间；一次点击、重复零次、首手势在五秒窗口内。
2. 旧事件无法再次点击，且不覆盖新安排或真实历史。
3. 当日消费后改晚、停用再启用及新进程恢复，均阻止当天再次自动开始。
4. 缺权编辑、重新授权不自动启用、定时准备/试运行/保存期间的紧急停止。
5. 超时跳过、存储/平台失败、无修改、旋转、大字体及横屏回归。
6. 同一安装包中检查编辑入口、精确定时状态和新桌面图标。

报告区分本轮联合验收与两边历史独立验收，不将不同运行轮次汇总写成单次全绿。真实手势、按钮接收及目标应用业务结果分别表述。真机/厂商后台策略和实际重启继续单独列为未验收范围。
